# V2 界面打磨与验证

日期：2026-10-30。版本：2.0.0-beta.2。范围：只改本地 V2 的界面，不推送、不发布。V1.1、处理引擎、代号格式、存储结构和钥匙文件的 JSON 字段都没有改动。

## 起因

前几轮功能逐步叠加，界面上积累了这些问题：
- styles.css 有两套颜色变量，前一套已经被后一套覆盖，形同废弃。
- 字号有 20 多种，字重有 11 档，正文大量使用 10–11px。
- 次要文字在浅色和深色主题下都有对比度不达标的地方。
- 同一个概念有 4–5 种叫法。
- 首屏有 4 处在讲同一条流程。
- 用户最需要核对的"替换了什么"要打开抽屉才能看到。

本轮先用内置浏览器截图走查，再做代码盘点，然后由用户确认改动深度和术语，最后分四个阶段实施。

## 已确认的决定

- 保留现有风格和整体布局，系统打磨，不改成分步向导。
- 界面用词统一如下。代码标识符、存储键和 JSON 字段都不改，对照表见 [CONTEXT.md](../CONTEXT.md)。

| 概念 | 界面用词 | 不再使用 |
| --- | --- | --- |
| 替换后的文字 | 代号（简短模式称"简短代号"） | 替身、语义代号、正式代号 |
| 任务标识 | 任务编号 | 任务指纹、任务标记、四位标记、任务代号 |
| 本机保存的对应关系 | 还原记录 | 映射、对照表 |
| 简短模式的 JSON 文件 | 还原钥匙文件 | 凭据 |

## 改动内容

### 同日先行修复（72993ab）

在内置浏览器里跑本地往返时发现了 3 个问题，本轮之前已经修复：
- 切换模式时用的是原生 `confirm`，在部分内嵌浏览器里会被自动取消。现改为页面内的确认对话框（`src/ConfirmDialog.jsx`）。
- 还原文件名会重复任务编号，或者带上完整 UUID。现统一为 `还原文件_<编号>`。
- 操作记录里，简短任务有时显示 4 位编号，有时显示完整编号。现统一显示 4 位编号。

### 阶段 1：变量、字号与对比度（2ca27e4）

- 废弃的颜色变量块改为通用尺度变量：`--fs-*`、`--fw-*`、`--sp-*`、`--radius-*`、`--focus-ring`。
- 原来 10–11px 的正文统一升到 12px，只有 3 个序号徽标保持原尺寸。
- 字重收敛为 400/600/700 三档，圆角收敛为四档。
- 两种主题的 `--faint` 都调深了，并去掉了深色主题下不达标的写死颜色。焦点描边改为跟随主题强调色。

### 阶段 2：术语与文案（59fd7cb）

- 全站按术语表替换用词。钥匙文件下载名改为 `还原钥匙_XXXX.json`。导入时只校验文件内容，所以旧名字的文件仍能导入。
- 删去所有"首版"说法，"兼容性预检"改为"文件检查"。
- 错误指引控制在 40 字左右。AI 处理说明压缩到约 70 字，测试依赖的关键句保持不变。
- 存储说明压缩为 3 条，技术细节单独成段。界面上不再写死访问地址，改为读取当前地址。
- 按钮名称统一："换一个文件"、"查看检查详情"。

### 阶段 3：布局去重（121e0c1）

- 顶栏路径和手机端进度条都会按当前步骤高亮，并标注 `aria-current="step"`。
- 准备状态直接列出前 4 项替换内容。代号格式收进默认折叠的"高级选项"，选了简短代号后自动展开。
- 去掉标题区与左侧任务卡重复的眉标。"交给 AI 前请复核其余内容"只在成功状态出现一次。
- 抽屉不再重复主区域已有的三项脱敏指标。"当前支持范围内的检查通过"改为"检查通过"。

### 阶段 4：操作路径（c51ad94、d5d69dc）

- 检查文件时显示"正在检查文件"，不再一律显示"正在生成"。
- 下载后点"导入 AI 处理后的文件"，会切到还原模式并直接打开文件选择框，减少一次点击。
- 简短代号文件等待钥匙文件时，"选择还原钥匙文件"作为主按钮显示。

## 验证结果

| 验证项 | 结果 |
| --- | --- |
| 单元、可复现资产、打包、构建 | 81 / 10 / 5 项通过，构建通过 |
| 四浏览器完整回归 | 阶段 2 和阶段 4 各完整运行一次，均为 180 项全部通过（Chromium、Firefox、WebKit、390px） |
| 集中记录测试 | 后端 7 项、浏览器 20 项通过，使用隔离 PostgreSQL 和虚构身份 |
| 字号扫描 | 浅色、深色、390px 下没有小于 12px 的可见文字 |
| 对比度脚本 | 浅色和深色主题在空状态、准备、抽屉、成功四个状态下均无真实不达标项 |
| 旧术语扫描 | `src/` 中界面可见的旧术语清零。Excel 隐藏工作表里的"任务指纹"标签属于文件格式，保持不变 |
| 打开文件选择框 | Chromium、Firefox、WebKit 下点击"导入 AI 处理后的文件"都会打开文件选择框 |

几点说明：
- 阶段 1 的完整回归为 179/180。剩下的 1 项是 WebKit 抽屉动画测试在高负载下超时，单独连跑 3 次都通过，之后两次完整回归也都通过。
- 阶段 3 的完整回归有 12 项失败，原因都是断言依赖旧结构（代号格式被收起、旧的检查结论文案）。更新断言后，这 12 项在四个浏览器上复跑通过；阶段 4 的完整回归再次 180 项全部通过。
- 对比度脚本对渐变按钮上的白字测不准，这类误报已人工复核排除。脚本不能替代整站 WCAG 认证。

## 过程说明

执行期间，从本对话分叉出的侧边会话曾在同一文件夹里执行 `git checkout -- src/styles.css`，把阶段 1 的未提交改动清掉了。随后用保存的转换脚本完整重放，重放后的结果经过测试再提交。此后改为每个阶段完成即提交。按用户决定，侧边会话不再修改文件。
