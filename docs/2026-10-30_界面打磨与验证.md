# V2 界面打磨与验证

日期：2026-10-30。版本：2.0.0-beta.2。范围：只改本地 V2 的界面，不推送、不发布。V1.1、处理引擎、代号格式、存储结构和钥匙文件的 JSON 字段都没有改动。

## 起因

前几轮功能逐步叠加，界面上积累了这些问题：
- styles.css 有两套颜色变量，前一套已经被后一套覆盖，形同废弃。
- 字号有 20 多种，字重有 11 档，正文大量使用 10–11px。
- 次要文字在浅色和深色主题下都有对比度不达标的地方。
- 同一个概念有 4–5 种叫法。
- 首屏有 4 处在讲同一条流程。
- 用户最需要核对的"替换了什么"要打开抽屉才能看到。

本轮先用内置浏览器截图走查，再做代码盘点，然后由用户确认改动深度和术语，最后分四个阶段实施。

## 已确认的决定

- 保留现有风格和整体布局，系统打磨，不改成分步向导。
- 界面用词统一如下。代码标识符、存储键和 JSON 字段都不改，对照表见 [CONTEXT.md](../CONTEXT.md)。

| 概念 | 界面用词 | 不再使用 |
| --- | --- | --- |
| 替换后的文字 | 代号（简短模式称"简短代号"） | 替身、语义代号、正式代号 |
| 任务标识 | 任务编号 | 任务指纹、任务标记、四位标记、任务代号 |
| 本机保存的对应关系 | 还原记录 | 映射、对照表 |
| 简短模式的 JSON 文件 | 还原钥匙文件 | 凭据 |

## 改动内容

### 同日先行修复（72993ab）

在内置浏览器里跑本地往返时发现了 3 个问题，本轮之前已经修复：
- 切换模式时用的是原生 `confirm`，在部分内嵌浏览器里会被自动取消。现改为页面内的确认对话框（`src/ConfirmDialog.jsx`）。
- 还原文件名会重复任务编号，或者带上完整 UUID。现统一为 `还原文件_<编号>`。
- 操作记录里，简短任务有时显示 4 位编号，有时显示完整编号。现统一显示 4 位编号。

### 阶段 1：变量、字号与对比度（2ca27e4）

- 废弃的颜色变量块改为通用尺度变量：`--fs-*`、`--fw-*`、`--sp-*`、`--radius-*`、`--focus-ring`。
- 原来 10–11px 的正文统一升到 12px，只有 3 个序号徽标保持原尺寸。
- 字重收敛为 400/600/700 三档，圆角收敛为四档。
- 两种主题的 `--faint` 都调深了，并去掉了深色主题下不达标的写死颜色。焦点描边改为跟随主题强调色。

### 阶段 2：术语与文案（59fd7cb）

- 全站按术语表替换用词。钥匙文件下载名改为 `还原钥匙_XXXX.json`。导入时只校验文件内容，所以旧名字的文件仍能导入。
- 删去所有"首版"说法，"兼容性预检"改为"文件检查"。
- 错误指引控制在 40 字左右。AI 处理说明压缩到约 70 字，测试依赖的关键句保持不变。
- 存储说明压缩为 3 条，技术细节单独成段。界面上不再写死访问地址，改为读取当前地址。
- 按钮名称统一："换一个文件"、"查看检查详情"。

### 阶段 3：布局去重（121e0c1）

- 顶栏路径和手机端进度条都会按当前步骤高亮，并标注 `aria-current="step"`。
- 准备状态直接列出前 4 项替换内容。代号格式收进默认折叠的"高级选项"，选了简短代号后自动展开。
- 去掉标题区与左侧任务卡重复的眉标。"交给 AI 前请复核其余内容"只在成功状态出现一次。
- 抽屉不再重复主区域已有的三项脱敏指标。"当前支持范围内的检查通过"改为"检查通过"。

### 阶段 4：操作路径（c51ad94、d5d69dc）

- 检查文件时显示"正在检查文件"，不再一律显示"正在生成"。
- 下载后点"导入 AI 处理后的文件"，会切到还原模式并直接打开文件选择框，减少一次点击。
- 简短代号文件等待钥匙文件时，"选择还原钥匙文件"作为主按钮显示。

## 后续：回归稳定性

此前全量回归每轮随机有 1–2 项失败。逐项查证后原因分三类，此前把它们都归为高负载超时并不准确：

- **WebKit 用例偏慢**：平均约为 Chromium 的 3 倍，p90 约 25 秒，30 秒上限过紧。WebKit 项目的上限改为 60 秒。
- **WebKit 动画帧停滞**：有一次等待元素稳定超过 60 秒，加大超时没有用，判断为 Windows 上的 WebKit 在高并行下动画帧停滞。并行数从 6 降到 4。这一条是根据现象推断的，未直接证实。这里写死的 4 同时作用到了 CI：CI 原本是 1 个 worker，全部通过；改成 4 之后连续两次失败（34 项、6 项）。现已改为 CI 用 1、本机用 4，`browser` 检查 196 项全部通过。
- **依赖审计**：`minimatch` 低于 11.0.1 的中危告警（GHSA-g3hv-75wg-m249）让 `test` 检查失败。已在 `overrides` 中把 `exceljs` 依赖树里的 `minimatch` 固定为 11.0.3，审计清零。已知副作用：依赖树里的 `glob@7` 与它不完全兼容，`glob.sync` 调用会报错。这条路径只有 `archiver.glob` 和带通配符的 `rimraf` 会走到；实测 ExcelJS 读写工作簿时 `glob` 调用次数为 0，构建产物也不含 `glob`。今后升级 `exceljs` 时应重新评估并尽量去掉这条覆盖。
- **测试竞争**：切换模式是异步的，有测试没等切换完成就上传文件，已修复。

另有一次 Firefox 手动添加候选失败：输入框为空且无报错。88 次重复未能复现，原因未查明。推测是抽屉打开时的焦点回调被延后，抢走了正在输入的焦点。已改为焦点已在抽屉内时不再移动，这一改动本身合理，但不能确认就是该次失败的原因。

验证：修改后连续两轮四浏览器 196 项全部通过（各约 4.5 分钟），单元测试 84 项、集中记录 10 + 20 项通过。此前平均每轮约 1–2 项失败，两轮样本还不足以断定问题已彻底消除。

### HTML 图表还原（2026-11-03）

- 已确认的决定：还原版保留图表脚本，用安全策略限制联网，而不是继续做成纯静态页面。
- 保留的脚本：内嵌脚本，以及从 jsdelivr、cdnjs、unpkg 加载的脚本（类型为空、JavaScript 或 module）。其他来源的脚本、`text/template` 等非脚本类型、事件属性、表单、嵌入页面照旧移除。脚本统一放回正文末尾，保持原顺序，保证图表脚本能找到画布。
- 代号：内嵌脚本里的代号参与核对并还原。真实值写回时把引号、反斜杠、`$`、`<`、`>` 和换行转成 `\uXXXX`，放进任何一种字符串都不会断开，也写不出 `</script>`。CDN 脚本的地址或内容里出现代号时仍然拦截。
- 安全策略（有脚本时）：`script-src` 只放行内嵌脚本和上述三个 CDN，`connect-src 'none'`、`frame-src 'none'`，图片只允许 `data:` 和 `blob:`，禁止表单提交。没有脚本时仍用原来的严格静态策略，输出也仍是普通静态页面。
- 隔离框架（堵跳转外传）：有脚本时，还原版是一个外壳页面，真正的页面放在 `<iframe sandbox="allow-scripts" srcdoc>` 里运行。沙箱禁止弹窗、禁止改动外层窗口地址、禁止提交表单；框架自己跳转时按外壳的 `frame-src 'none'` 拦下。外壳本身没有脚本，与内页使用同一条安全策略（srcdoc 会继承外壳的策略）。
- 前置脚本（堵 WebRTC）：WebRTC 不受安全策略约束，所以内页最先运行一段前置脚本：删除 `RTCPeerConnection` 等构造函数，并封住重新拿到它的路子（嵌套框架会被立即移除，`document.write` 和 Shadow DOM 被禁用）。
- 检查页提示改为“还原版保留了 N 段图表脚本，在隔离框架中运行，不能联网、弹窗或跳转”。
- 验证：单元测试覆盖保留、转义（含引号、`</script>`、反斜杠、`${}`）、外壳和前置脚本、拦截；界面测试的 HTML 样本已加入 Chart.js 图表。在 Chromium 中用本机监听器（HTTP 和 UDP 各一个端口）实测：不加防护的页面能通过 WebRTC 发出 UDP 包；只加沙箱时，跳转、弹窗、表单、图片、`fetch` 都被挡住，但 WebRTC 仍能从页面本身、嵌套框架、Shadow DOM 和 `document.write` 四条路发出；加上前置脚本后，以上全部被挡住，监听器没有收到任何请求。还原版图表正常绘制，分类显示真实客户名。
- 仍然存在的限制：被拦下的框架跳转会让框架变成空白（只有恶意页面会这样）；打印时只打印框架可见区域；Firefox 和 Safari 只跑了界面测试，没做监听器实测；DNS 预取等浏览器内部机制没有逐一验证。
