## 0. 背景与已定决策

用户的真实需求：把文件里的公司名、人名等敏感内容换成代号，再交给 AI；AI 处理后再换回来。今天实际测试暴露的问题：表格结构一复杂就失败、界面概念太多（“列”“其他名称”“替换方式”）。

已和用户确认的决定：

1. **按文件类型决定替换方式**
   - CSV、Excel 里**表格型**的区域 → **按列**：勾选哪几列，这些列里的值就是要保护的名称。
   - TXT、Markdown、Word、Excel 里**非表格型**的区域（表单、说明、组织架构）→ **按关键词**：系统给出候选，用户勾选或手动添加。
2. **全文件替换**：无论来自列还是关键词，确认的名称会在整个文件所有位置换成同一个代号（Excel 已实现，见 `replaceAcrossWorkbook`）。
3. **去掉“替换方式”（整个单元格 / 仅文中已选内容）选项**，由系统自动判断。
4. **去掉“其他名称”这个说法**，界面只有“需要替换的列”和“需要替换的关键词”两种。
5. 电话、身份证号、银行卡号要**自动识别并建议替换**。
6. 不做 WPS 格式（.et/.wps）支持；跨文件统一代号放到下一版；工作表名称、批注自动改写以后再说。

## 3. 第 1 批：去掉替换方式 + CSV 全文件替换（低风险）

### 3.1 去掉“替换方式”选项
- `SecurityDrawer` 的 `renderColumns`：删除每列的 `Dropdown`（替换方式）；删除“整个单元格 / 仅文中已选内容”说明段和“当前全部选为仅文中已选内容”警告。
- 每列的处理方式改为**自动**：`processingMode = column.recommendedMode ?? "whole"`（`recommendedProcessingMode` 已按表头判断长文字列）。长文字列在列卡片的小字里注明“长文字：只换句子里的名称”，其他列不显示方式。
- `App.jsx` 里的 `fieldModes` 状态、`changeProtectionMode`、`onModeChange` 一并清理；`ReadyState` 预览卡片的 detail 改为“42 个值”或“长文字 · 只换句子里的名称”。
- `hasOnlyInlineFields`：只有当所有勾选列都是长文字列、**且**没有勾选任何关键词时才提示，文案改成“请至少勾选一列名称（例如客户名称、业务员），系统才知道长文字里该换哪些词”。
- 受影响测试：`tests/e2e/smoke.spec.js`（第 30、169 行附近断言替换方式的 `data-value`）、`tests/e2e/csv-hardening.spec.js`（第 82 行附近选择替换方式）、`tests/e2e/empty-column.spec.js`。改成断言自动判断的结果。

### 3.2 CSV 全文件替换
- 在 `csvCore.js` 的 `tokenizeCsv` 末尾，仿照 `xlsxCore.js` 的 `replaceAcrossWorkbook`：对**未勾选列**的所有数据单元格（不含表头行），用 `spreadsAcrossWorkbook` 过滤后的名单做“整格完全相等 → 代号”和“长文字里出现 → 就地替换”（用 CSV 已有的 `replaceKnownEntities(value, entityIndex)`）。统计 `elsewhere = { cells, columns: [{ header, cells }] }`。
- `csvEngine.js` 把 `elsewhere` 带进结果；`App.jsx` 的 `elsewhereSentence` 对 CSV 显示“除了所选的列，还在「备注」「跟进记录」2 列里替换了 N 处相同的名称”。
- 受影响测试：`tests/e2e/smoke.spec.js` 的“CSV 取消叙述列时阻止真实值残留…”、`tests/e2e/format-roundtrip.spec.js` 的“CSV 列内残留可一键加入…”——这些原来期望被拦下，现在应直接生成成功并说明额外替换的位置；短编号（如 3 位）在其他列出现时仍应拦下并说明位置。
- 新增单元测试（放进 `tests/csv-core.test.mjs`）：备注列里的客户名被替换且还原一致；数量列等于客户编号的数字不被替换。

**验收**：`npm run test:unit` 全过；上述 e2e 在 chromium 通过；浏览器里用一个带“备注”列的 CSV 演示一遍并截图给用户。

## 4. 第 2 批：关键词位置 + 隐藏内容提示 + 电话证件号（低风险）

### 4.1 关键词显示出现位置（Excel）
- `workbookCandidates.js` 生成候选时记录 `locations: [{ sheet, row, column }]`（`column` 是数字）。
- `TextCandidateSelection` 的紧凑模式：名称后面显示第一个位置“「重点客户资料表」第 4 行 B 列”，多处时加“等 3 处”；鼠标悬停显示那一格原文（现有 `contexts[0]`）。位置格式化可复用 `src/errorPresentation.js` 的 `residualPlace`。
- 手动添加的关键词同样计算位置（在工作簿里查找完整文字）。

### 4.2 隐藏内容提示（Excel）
- `xlsxEngine.inspectProtectionFile` 统计：隐藏 / 深度隐藏的工作表（排除 `__AI安全任务`）、隐藏行数、隐藏列数（ExcelJS：`worksheet.state`、`row.hidden`、`column.hidden`）。
- `ReadyState` 显示提示条（样式同图片提示 `task-change-banner`）：“文件里有 2 个隐藏工作表、5 行隐藏行。它们会和其他内容一样被替换，并一起交给 AI，请确认里面没有不该给 AI 的内容。”没有隐藏内容时不显示。

### 4.3 电话、身份证号、银行卡号自动建议替换
- 现有 `fileSafety.js` 的 `highRiskTextFindings` 只做提醒。改为生成**关键词候选**（Excel 走 `workbookCandidates.js`，文本类走 `textCore.analyzeText`），标签分别为“手机号”“固定电话”“身份证号”“银行卡号”“邮箱”，默认勾选。
  - 手机：`1[3-9]\d{9}`（前后不能紧挨数字）；固话：`0\d{2,3}-?\d{7,8}`；身份证：18 位且**校验位正确**；银行卡：16–19 位且**通过 Luhn 校验**；邮箱：常规写法。
- 表头为“电话 / 手机 / 联系方式 / 身份证 / 证件号 / 银行账号 / 卡号 / 邮箱”的列，在 `classifyHeader` 里归为可自动勾选的一类（前缀用 `X`，标签用表头文字），整列替换。
- 这些都是纯数字，`spreadsAcrossWorkbook` 不会全文件替换；作为**用户确认的关键词**会走 `force`（已支持），整格相等或长文字里出现时替换。注意不要误伤金额：只认上面的格式和校验位。
- 新增单元测试：正确/错误校验位的身份证、能/不能通过 Luhn 的卡号、手机号前后有数字时不认。

**验收**：单元测试全过；用 `tests/fixtures/customer-profile-workbook.mjs` 加上一行电话和身份证（虚构、校验位正确）演示；截图给用户。

## 5. 第 3 批：界面整合（中风险，注意设计质量）

目标：用户只看到和自己文件相关的部分，“列”和“关键词”各管各的。

- **CSV、纯表格型 Excel**：抽屉只有“需要替换的列”（已勾选和建议的列在前，其余折叠在“其他 N 列”）。只有在**没勾选的列里找到名称**时，才在下方显示关键词区，标题“没勾选的列里还有这些名称”，说明“例如写在备注里；勾选的会一起替换”。
- **TXT、Markdown、Word**：只有“需要替换的关键词”（现有 `TextCandidateSelection`，非紧凑模式）。
- **混合型 Excel**（既有表格区域又有非表格区域）：两块都显示；关键词区标题“需要替换的关键词”，说明“以下工作表不是表格，按关键词替换：重点客户资料表、组织架构……”（列出非表格的工作表名）。
- 删除“其他名称”这个标题；`ReadyState` 的汇总文字改为“已选择 3 列、10 个关键词”，卡片标题“确认替换内容”。
- 手动添加始终可用，提示“系统认不全简称和昵称（如“马总”），可以在这里补充”。
- **设计要求**：先截图自查（浅色、深色、手机宽度 375px、1440 宽屏），对齐、留白、层级清楚，没有横向滚动，再交给用户看。

**验收**：三类文件（CSV、Word、仿东骏的混合 Excel）各截一张抽屉图给用户确认。

## 6. 第 4 批：按区域识别表格（高风险，先写测试再改代码）

现状：`analyzeWorkbook` 每个工作表只找**一行**表头（`detectHeaderRow`），整张表其余行都当数据。问题：

- 同一工作表上半部分是表单、下半部分是表格（东骏“重点客户资料表”下方的“品种分析表”“销售跟进记录”）。
- 一个工作表里并排或上下有多个小表格（东骏“成本核算”：三个配方表左右并排）。

做法：

1. **先写测试夹具和断言**（`tests/fixtures/` 新增或扩展 `customer-profile-workbook.mjs`）：
   - 表单 + 下方表格；三个并排小表格；正常单表（回归保护，结果必须和现在一致）。
   - 断言每个工作表识别出的表格区域（表头行、起止列、结束行）。
2. 在 `xlsxCore.js` 新增 `detectTableBlocks(worksheet)`：
   - 表头行：连续 ≥3 个非空、较短的文字单元格。
   - 表格区域：表头下方至少 2 行，在这些列里大部分有值；遇到整行空白或明显不同形状的行结束。
   - 同一行里被空列隔开的多组表头，算多个表格。
   - 不在任何表格区域里的单元格，算“非表格区域”，交给 `workbookCandidates.js` 按关键词识别（现有 `headerRows` 参数需要改成按区域判断）。
3. 列的 id 已包含表头行（`candidateId(sheet, headerRow, column)`），给列加上 `endRow`；`tokenizeWorkbook` 和 `analyzeWorkbook` 的取值循环只到 `endRow`。
4. **还原不能受影响**：还原按代号查找，不依赖列识别，但每个测试都要做“生成 → 还原 → 逐格比对与原文件一致”。

**验收**：新旧测试全过；`tests/workbook-candidates.test.mjs`、`tests/xlsx-workbook-wide.test.mjs`、`tests/multi-fixture-roundtrip.test.mjs` 的结果不能变；浏览器里用仿东骏文件演示并截图。
