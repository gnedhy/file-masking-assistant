# 部署指南

适用于公司内部部署：一个应用容器加一个 PostgreSQL 容器，前面由 HTTPS 反向代理转发。

**使用方式：** 员工只能从企业微信工作台打开（电脑版或手机版企业微信）。用 Chrome 等普通浏览器直接打开会登录失败，因为静默登录只在企业微信内置浏览器里有效。

## 一、部署前要准备的信息

| 项目 | 说明 |
| --- | --- |
| 服务器 | 能运行 Docker 和 Docker Compose 的 Linux 主机，建议 2 核 4 GB 以上，磁盘按记录量预留 |
| 访问地址 | 例如 `https://file-mask.example.corp`，必须是 HTTPS，且**能从外网访问**：企业微信要从外网校验可信域名，员工在公司外用手机企业微信也要能打开。域名一般还要求 ICP 备案主体与企业一致，请向企业微信管理员确认 |
| HTTPS 证书 | 由反向代理（Nginx、Caddy 或公司网关）负责。必须是正规机构签发的证书，公司自签证书在手机企业微信里通常打不开 |
| 企业微信自建应用 | 企业 ID（CorpID）、应用 AgentId、应用 Secret |
| 可信域名 | 在企业微信应用的“网页授权及 JS-SDK”中把访问地址的域名设为可信域名，通常要上传企业微信给的校验文件 |
| 企业可信 IP | 在应用里填服务器访问外网的出口 IP。2022 年 6 月 20 日后新建的自建应用不配就调不通企业微信接口，表现为登录失败 |
| 应用主页 | 填访问地址（如 `https://file-mask.example.corp/`），员工从工作台点开即静默登录，不需要输入账号 |
| 可见范围 | 选择能使用的部门或人员；范围外的人打不开应用，也读不到姓名 |
| 管理员名单 | 能查看全部人操作记录的企业微信 userId，多个用逗号分隔 |

### 服务器网络

| 方向 | 要求 |
| --- | --- |
| 构建时 | 能拉取 Docker Hub 的 `node:22-alpine`、`postgres:17-alpine`，能访问 npm 仓库。国内服务器常拉不下来，需提前配置镜像加速或公司内部镜像源 |
| 运行时（出站） | 能访问 `https://qyapi.weixin.qq.com`。服务器的出口 IP 必须填进企业微信应用的“企业可信 IP”，否则登录失败 |
| 运行时（入站） | 只开放反向代理的 443 端口；应用的 8080 端口只给本机反向代理使用 |

### 企业微信可信域名校验文件

设置可信域名时，企业微信会给一个校验文件（如 `WW_verify_xxxx.txt`），要求能通过 `https://域名/WW_verify_xxxx.txt` 访问到。应用本身不提供这个文件（未知路径都会返回首页），请在反向代理里单独返回，见第三节 Nginx 示例。

## 二、准备配置

在部署目录执行：

```bash
cp .env.enterprise.example .env.enterprise
mkdir -p secrets
openssl rand -base64 32 > secrets/vault_master_key.txt
openssl rand -hex 32 > secrets/session_secret.txt
printf '%s' '企业微信应用 Secret' > secrets/wecom_secret.txt
# 容器内以 node 用户（编号 1000）运行，密钥文件要归它所有，否则应用读不到、启动失败
chown 1000:1000 secrets/*
chmod 400 secrets/*
```

编辑 `.env.enterprise`：

- `POSTGRES_PASSWORD`：随机长密码，只用字母和数字，避免 URL 转义问题。
- `PUBLIC_ORIGIN`：访问地址，不带结尾斜杠，必须和企业微信可信域名一致。
- `WECOM_CORP_ID`、`WECOM_AGENT_ID`：企业微信应用信息。
- `ADMIN_USER_IDS`：管理员 userId，改动后重启应用即生效。
- `COOKIE_SECURE=true`：HTTPS 部署时保持开启。
- `VAULT_KEY_VERSION=v1`：保持不变。目前没有密钥轮换流程，改动后旧的还原记录无法解密。

访问地址必须统一：企业微信应用主页、可信域名和 `PUBLIC_ORIGIN` 要完全一致。用 IP 或其他域名打开时，登录会提示“企业微信登录状态无效”，或请求被安全检查拒绝。

## 三、启动

```bash
docker compose --env-file .env.enterprise up -d --build
docker compose ps
curl -s http://127.0.0.1:8080/readyz
```

`readyz` 返回 `{"status":"ready"}` 表示应用和数据库都正常。数据库表在首次启动时自动创建，之后每次启动会自动补齐新字段，可以重复执行。

应用只监听本机 `127.0.0.1:8080`，由反向代理把 HTTPS 流量转过来。Nginx 示例：

```nginx
server {
  listen 443 ssl;
  server_name file-mask.example.corp;
  client_max_body_size 4m;
  # 企业微信可信域名校验文件：文件名和内容换成企业微信后台给的
  location = /WW_verify_xxxx.txt {
    default_type text/plain;
    return 200 'xxxx';
  }
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
  }
}
```

文件只在浏览器里处理，服务器只接收还原记录（单次上限 2 MB）和操作记录，所以 `client_max_body_size` 不需要按文件大小放大。

只部署一个应用实例。请求限流计数保存在应用内存里，多开实例不会出错，但限流会各算各的；目前不需要扩容。

## 四、上线验收

1. 在企业微信工作台打开应用，能自动登录并看到首页；“操作记录”里显示的是本人姓名而不是 userId（显示 userId 说明读取成员失败，检查可信 IP 和可见范围）。
2. 用一份虚构样本完成“脱敏 → 下载 → 还原”，结果与原文件一致。
3. 换一台电脑，用同一账号还原第 2 步的脱敏文件。
4. 用另一位同事的账号还原该文件，应提示“找不到这个文件的还原记录”。
5. 管理员账号在“操作记录”里能看到“使用统计”，普通账号看不到；管理员打开后，记录里会多一条“查看全员记录”。
6. 分别用**电脑版**和**手机版**企业微信完成一次“脱敏 → 下载”。手机版内置浏览器对下载的支持不稳定；如果手机下载不了，通知员工使用电脑版企业微信。
7. 断开公司网络，用手机流量在企业微信里打开应用，确认外网能访问。

### 常见问题

| 现象 | 先查 |
| --- | --- |
| 应用容器反复重启，日志提示读不到 `/run/secrets/...` | 密钥文件归属和权限（第二节 `chown`、`chmod`） |
| 打开后提示“企业微信登录状态无效” | 应用主页地址是否与 `PUBLIC_ORIGIN` 完全一致（协议、域名、端口） |
| 打开后提示“无法确认企业微信用户”或“企业服务暂时不可用” | 企业可信 IP、应用 Secret 是否填对、服务器能否访问 `qyapi.weixin.qq.com` |
| 企业微信提示 redirect_uri 与配置的可信域名不一致 | 可信域名是否已校验通过，`PUBLIC_ORIGIN` 是否与可信域名完全一致 |
| 能登录，但显示 userId 而不是姓名 | 企业可信 IP、应用可见范围 |
| 手机企业微信打不开页面 | 证书是否正规机构签发、域名能否从外网访问 |

## 五、备份与恢复

**主密钥和数据库要分开备份。** 只有数据库没有主密钥，记录无法解密；两者放在一起，泄露风险加倍。

```bash
docker compose exec -T postgres pg_dump -U filemask -Fc filemask > backup/filemask_$(date +%F).dump
```

- `secrets/vault_master_key.txt` 单独存放到密码库或离线介质，丢失后所有还原记录不可恢复。
- 至少每周演练一次恢复：用 `pg_restore` 导入到临时库，确认能启动并读到记录。

## 六、升级与回滚

```bash
git pull
docker compose --env-file .env.enterprise up -d --build
```

升级前先备份数据库。数据库结构只做新增字段，不删除已有数据（唯一例外是不再使用的 `expires_at` 字段）。回滚到旧版本时，请同时恢复升级前的数据库备份。

## 七、注意事项

- 还原记录不自动到期，用户可在“我的任务”里删除；删除后对应文件不能再还原。
- 操作记录保留 180 天，到期自动清理。
- 服务器或数据库不可用时，页面会停止脱敏和还原，不会生成无法还原的文件。
- 不要把 `secrets/`、`.env.enterprise` 提交到代码仓库（`.dockerignore` 和 `.gitignore` 已排除）。
