# 2026-08-19 项目现状与验证基线

## 结论

当前版本已经超过纯视觉原型，属于可运行的浏览器功能验证版。核心格式引擎与失败关闭规则有自动化证据，但还不能宣称生产稳定或达到正式企业安全产品标准。

## 当前能力

| 流程 | 支持格式 | 当前边界 |
| --- | --- | --- |
| 制作脱敏文件 | XLSX、CSV、TXT、MD、DOCX | 表格确认字段；非表格确认候选内容和上下文后创建任务专属代号 |
| 还原处理文件 | XLSX、CSV、TXT、MD、DOCX、PPTX、安全静态 HTML | 只处理已声明文字区域；HTML 允许受控部分还原，其余危险情况停止输出 |
| 本机任务 | 当前浏览器 | 显示任务、映射数量和状态，可逐项删除 |

## 本次验证证据

- 自动化测试：63 项通过，覆盖 XLSX、CSV、TXT、MD、DOCX/PPTX、HTML、统一预检、本机映射与站点打包。
- 浏览器 E2E：18 项通过，桌面与 390px 各覆盖制作、还原、主题、抽屉、失败关闭、部分还原、Markdown、DOCX 完整往返，以及真实短编码边界场景。
- 生产构建：通过；主应用包约 473 kB，Office、HTML 与纯文本处理器已按需加载；ExcelJS 独立包约 940 kB。
- 依赖审计：生产依赖 `npm audit --omit=dev` 为 0；测试样本生成依赖仍有已记录的开发期例外，见 `2026-08-20_依赖安全审计.md`。
- 窄屏检查：390px 无横向溢出；浅色、深色和系统主题均有浏览器回归。
- 可复现样本：一条命令生成映射及 CSV、TXT、MD、DOCX、PPTX、HTML 样本，不依赖桌面目录、真实企业文件或外部模板。

## 安全与可靠性缺口

1. 浏览器密钥和密文映射仍在同一浏览器环境；已验证并发创建、密钥丢失、密文损坏和存储不可用的失败关闭，但不等同于企业密钥托管或安全删除。
2. DOCX 自动化已覆盖正文、表格、页眉页脚、文本框、跨文字片段和复杂结构拦截；Microsoft Word 已完成自动打开验证，仍缺 WPS 和 LibreOffice 的人工打开证据。
3. 图片不扫描；图表、SmartArt 和嵌入对象不主动处理。DOCX 脱敏遇到批注、脚注/尾注、修订、内容控件或域时停止生成。
4. 还缺少覆盖真实 AI 来源的长期兼容性矩阵；工程测试通过不等于完成 50 份文件、2–4 周业务试用目标。

## 可维护性缺口

- `App.jsx` 仍集中承载多阶段状态和抽屉；已有 E2E 保护，后续只在真实维护成本出现时再拆分，避免为抽象而抽象。
- `styles.css` 仍包含多轮样式记录；主题变量和关键交互已统一，后续整理必须以视觉回归为前提。
- ExcelJS 仍是最大的按需包；首屏已不加载 Office、HTML 和纯文本处理器。

## 下一阶段原则

- 下一阶段先准备真实试用记录和 DOCX 多应用人工打开验证，不继续扩张首版格式承诺。
- 新格式必须完成“制作或还原入口 → 内容预检 → 任务匹配 → 失败关闭 → 原格式输出 → 自动化样本”的完整纵向闭环。
- PPTX 脱敏输入保持 P2，在真实试用完成后再实施；PDF、OCR、宏文件、嵌入对象和跨设备任务迁移继续保持范围外。
- 所有“稳定可用”结论都必须关联真实样本数量、AI 来源、试用周期和失败记录。
